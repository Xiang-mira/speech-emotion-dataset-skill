# 从已有录音开始

按原样保留源文件。用 `sample_id` 和项目内相对路径匹配 WAV。若仅有文件名，先从明确映射或来源记录确认对应关系。录音缺失时给出编号与缺件列表。音频解码、时长和静音检查通过后，由听审人确认语音完整清晰。

1. 明确本轮可选标签和复核方式，配入 `config.json`。匿名角色 `r1`、`r2` 分别初审，第三人路径由 `adjudicator` 定稿。按项目需要决定初审时是否显示录制文本。预设、提示和另一人的初判在独立提交时隔离。
2. 使用完整项目的本地听审网页。两位听审人在各自浏览器会话打开专属入口，页内播放完整音频，按听见的主情绪选择一个标签。遇到音质问题按页面标记。角色入口仅交相应人员。默认监听本机回环地址，适用于本机验收。
3. 两人提交后单列初审分歧。双方通过且标签一致的样本采用共同判断。有分歧的样本先留空，根据配置共同复听并确认同一版裁定，或交指定第三人复听，记录最终标签与理由。已一致后再改判须留下原判、理由和新版本。
4. 离线意见按评审角色和样本编号补入。已有相同值可重复导入，遇到不同值列出冲突并保留原值。定稿后下载 `final.csv` 和供内部追溯的 `audit.csv`。真实姓名、童声或其他敏感材料应按项目授权保存。

分阶段报告收到的音频数、两人均已完成的初审数、其中一致数和分歧数、已定稿数。初审一致率的分母为双方均已完成有效标签判断的样本数。分歧样本即使最后裁定为原预设，仍保留初审分歧记录。
