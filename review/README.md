# 双人语音听审

在仓库根目录运行下列命令。需要 Python 3.10 或更高版本。首次启动时，系统会在 `work/demo/` 建立工作副本，并使用本地中文语音引擎生成演示 WAV。语音引擎要求及手动补充方式见[仓库首页](../README.md)。

```sh
python run.py demo
```

## 开始听审

1. 终端为每个角色打印专属链接。将 `r1`、`r2` 各自的链接交给对应听审人。第三人裁定模式另有 `adjudicator` 链接。链接可以登录相应角色，须分别保管。
2. 同一台电脑上演示时，两个听审人使用不同浏览器、独立浏览器配置，或一个普通会话和一个无痕会话。同一浏览器配置中的多个标签页会共用登录身份。第三位使用另一个独立配置。默认仅本机可访问；团队远程听审需将服务部署到可访问的受控环境，并配置 HTTPS。
3. 打开样本，直接播放页面内的录音，判断实际听到的情绪。无法判断或音质不合格时选择相应选项并说明原因。每条提交后即保存原判，可在「阶段小结」查看自己的进度。本轮填写完毕后点击「提交整轮初审」。
4. 双方提交整轮初审后才显示两份原判。音质均合格且情绪一致时自动形成金标。待复核项可通过筛选定位，复听并填写新结论和依据。共同复核模式中，一方提出结论，另一方确认同一版本；指定复核人模式由该角色提交裁定。修订结论后会生成新版本。原判与操作历史可追溯。
5. 页面提供定稿清单和审核记录下载。定稿清单保留全部编号，合格且完成定稿的行才有 `human_label`。评分清单的导出与核验见[交付说明](../skills/speech-emotion-eval/references/delivery.md)。

## 切换自己的材料

项目目录至少包含 `collection.csv`、`config.json` 和实际 WAV。以[演示配置](../examples/demo/config.json)为起点，按本轮项目调整标签、`review_mode`（`joint` 或 `third`）、`checkpoint`（阶段条数）与 `show_text`（是否展示转写）。清单提供 `sample_id` 和相对 WAV 路径 `audio`，显示转写时还需 `text`。假设项目目录名为 `my-review`，运行 `python run.py review --project my-review` 即可听审真实录音。初审页只展示配置允许的信息，朗读预设及表演提示在采录端保留。

启动后，角色凭据和评审记录存于项目自己的 `.review/`。重启时使用同一项目目录可继续听审。已提交初审后需替换听审材料时，复制清单与新音频到新的项目目录开始新版本，保存旧项目以便追溯。备份项目时请保护包含凭据及原判的本地数据库。

## 离线补评

按听审人分别保存 UTF-8 CSV，表头为 `sample_id,label,quality,note`。`quality` 可取 `pass`、`uncertain` 或 `reject`。后两种需填写备注，标签可以留空。下例补入第一位听审人的离线判断。

```sh
python review/server.py --project my-review --role r1 --import-offline offline-r1.csv
```

程序按听审人和样本编号合并空缺，已有相同结果会跳过，冲突会列出。回到页面点击「刷新进度」核对合并结果，再提交整轮初审。
