# 发布前行为用例

分别在干净会话中以用户自然说法执行。保存实际文件和简要核验记录。同一输入另跑无技能或旧版，比较具体产物。下列预期用于评审，执行者只看任务与必要输入。

| 入口 | 用户说法及可用材料 | 怎样验收 |
|---|---|---|
| 只有需求 | “灯的状态和物品的位置我各想测一遍。每个场景要一条平静表达，再同人同句读开心和惊讶。给我六条可以录的中文题。”只给这一句话。 | 六个唯一编号、四段原文、两个合法对照组。两个场景各三条。提示与原文一致，无预填金标。逐组检查两种演法是否成立。 |
| 配额矛盾 | 要求普通 100 条且六类各 20 条，另有中性 20 条、15 组成对样本，并声明 170 条。 | 给出 150 和 170 两种算式，指出需要选择的口径。同步提供可独立确定的场景设计或样稿。 |
| 已有录音 | 提供演示清单与 WAV，将一份文件留在项目目录外，要求安排听审。 | 报告具体的缺件编号，保留其他可听任务。两人的初判互相隔离，分歧先留空，补录冲突保留原值。 |
| 已有定稿 | 给出完整真实定稿或人工构造的测试定稿和同批 WAV，给出接收端格式。 | 按编号关联，校对样本和配对，生成可被指定接收端读入的 JSONL。任一样本缺依据时不能报整批通过。 |
| 相邻任务 | 只要求将一段采访转写成文字。 | 直接处理转写，无需生成情绪标签或听审工程。 |

自动化断言适用于数量、重复、权限、版本、导出。文本的自然度、情绪可演性与听感由人工判断。合成演示的预设、脚本模拟的评分与真实听审结果分别标识。
